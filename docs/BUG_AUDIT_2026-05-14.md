# Bug Audit (2026-05-14)

Este documento lista **possíveis bugs** identificados por análise estática do repositório.

## 1) `GetNearbyHeroes` override pode retornar `nil` (quebra em loops)
- Arquivo: `bots/FunLib/aba_global_overrides.lua`
- Trecho: no override de `CDOTA_Bot_Script:GetNearbyHeroes`, quando `self:CanBeSeen()` é falso, a função retorna `nil`.
- Risco: o código do bot frequentemente itera listas de heróis com `for _,h in pairs(...)` / `ipairs(...)`. Se a função retornar `nil`, chamadas que não fazem guarda explícita podem gerar erro em runtime.
- Correção sugerida: retornar `{}` ao invés de `nil` para manter contrato de coleção.

## 2) `WasRecentlyDamagedByAnyHero` retorna `nil` para não-herói
- Arquivo: `bots/FunLib/aba_global_overrides.lua`
- Trecho: o override de `CDOTA_Bot_Script:WasRecentlyDamagedByAnyHero` retorna `nil` quando `not self:IsHero()`.
- Risco: muitos chamadores usam essa API como booleana. `nil` pode desviar lógica de prioridade/retreat de forma inesperada.
- Correção sugerida: retornar `false` para preservar semântica booleana.

## 3) `IsIllusion` retorna `nil` para unidade não visível
- Arquivo: `bots/FunLib/aba_global_overrides.lua`
- Trecho: `CDOTA_Bot_Script:IsIllusion()` retorna `nil` quando `not self:CanBeSeen()`.
- Risco: o restante do código costuma assumir bool puro; `nil` pode ser tratado como "desconhecido" e quebrar filtros de alvo/minion.
- Correção sugerida: retornar `false` (ou manter fallback para método original quando possível).

## 4) `GetMagicResist` força `1` (100%) para unidade invisível
- Arquivo: `bots/FunLib/aba_global_overrides.lua`
- Trecho: `CDOTA_Bot_Script:GetMagicResist()` retorna `1` quando a unidade não pode ser vista.
- Risco: isso pode induzir a IA a nunca conjurar magias em alvos temporariamente fora de visão (ou com visão instável), causando decisões ruins de combate.
- Correção sugerida: usar valor neutro menos extremo (ex.: estimativa por herói) ou manter valor anterior em cache em vez de 1.0 fixo.

## 5) Cache global de `GetTeamPlayers` para Dire não invalida
- Arquivo: `bots/FunLib/aba_global_overrides.lua`
- Trecho: `direTeamPlaters` é preenchido uma vez e nunca invalidado.
- Risco: em modos com reconnect/troca de slots/humano assumindo bot, o mapeamento pode ficar stale e quebrar seleção de IDs.
- Correção sugerida: invalidar cache por evento (hero selection/state change) ou por TTL.

## Observação de tooling
- `luac` e `luacheck` não estão disponíveis no ambiente atual; portanto a auditoria foi focada em revisão estática/manual e busca textual.
